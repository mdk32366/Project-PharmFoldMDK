## §1 — The span definition was wrong in four distinct ways, and the flagship protein was one

**`### F-025`.** `scripts/ecd_lengths.py:194-196` filtered `Topological domain` on the **substring**
`"extracellular"`. The band was called `no_topology` and **reported five different things**:
a reachable face under other vocabulary (553 annex / 106 surface) · a genuine annotation gap
(734 / 197) · **GPI-anchored, no topology by design** (1 / 125) · correctly excluded (199 / 15) ·
⚠ **the term matched and the coordinate was `UNKNOWN`** (0 / 1).

⚠ **The audit was ordered over twelve proteins and the data said thirteen.** The order selected on
`n_extracellular_spans == 0`; SDK1's is **1** — it matched and still had no span. **The criterion
chosen to find the defect was blind to one instance of it.**

⚠⚠ **And `Q13421` MSLN was folding 561 aa when its ectodomain is 302.** `min(Chain start)` took
residue 37, carrying ~250 residues of the megakaryocyte-potentiating factor — **cleaved and
secreted, so an antibody never meets it.** On the protein `F-025` is named after. **It would have
folded, scored, banded and looked entirely normal.**

⚠ **The first correction was also wrong and is recorded, not replaced.** Selecting *the chain whose
end coincides with the anchor* **excluded `P06731` CEACAM5** — a clinically-validated ADC target —
on a nine-residue mismatch at a boundary rule A never reads. **An exclusion on annotation form
rather than biology.** The rule is now *chains **containing** the anchor, latest start*.

**Also barred: rule B** (`Chain` start → `Chain` end). ⚠ **The check meant to validate it killed
it** — on all six divergent proteins `Chain` runs through the cleaved C-terminal GPI signal, by
**266 residues** on `Q96GW7`. It **fired zero times**, which is exactly why it was barred rather
than left: *a fallback that is unsafe when it fires is not a fallback.*

## §2 — ⚠⚠ The census fold path would have folded 3,468 whole sequences

`core/enqueue.py` branched on `boundary_method`, **not on the presence of coordinates**. Measured:

```
boundary_method='sliced_ecd'  -> AssertionError raised                     ✅
'whole' / '' / None / 'census_span'  -> FOLDED 2000 residues, source='whole'  ⚠ nothing red
```

**The safe branch required an exact literal; the unsafe branch was the DEFAULT, reached by
omission** — and the census manifest carried **no `boundary_method` column at all.** ⚠ `whole` is a
*legitimate* recorded outcome, so every artifact would have been internally consistent while
describing the wrong molecule 3,468 times.

⚠ **Found because a specified content-hash tuple named `span_start`/`span_end` and building it
found there were none.** The manifest had only `span_aa` — **a length, which cannot slice a
sequence.** *A specification acting as an audit.*

## §3 — The host bugchecked, and every instrument assumed it couldn't

An fp16 probe took the machine down: `0x0000001e`, Kernel-Power 41, unclean reboot. **Host RAM was
not the constraint.** ⚠ **On WDDM an over-allocation is not refused — the driver spills to system
memory**, and that path faulted in kernel mode.

⚠⚠ **`ceiling_probe._attempt` is `except Exception → OOM`. It never runs. There is no process
left.** And its append-only resume file — written *before* each fold precisely so a halt is
recoverable — came back as **55 bytes of `\0`**, because a hard reset does not flush the page cache.
**A probe built to survive its own failure mode did not survive it.**

**`### D-082`** followed. ⚠ **The bisection is what killed it**: 209 → 313 aa, a 50% jump into
unmeasured territory. The replacement **climbs**.

⚠ **Two of my diagnoses here were wrong.** I read `nvidia-smi`'s 7,658 MiB as demand and called the
card "94% full" — it is **reserved**, and true demand at 416 aa is **6,527**. And I reported the
0.85 cap as refuting `known_good = 440`; ⚠ **the cap binds on RESERVED, not demand** — 440 needs
6,664 allocated, comfortably under a 6,928 cap. **440 folds uncapped, and the constant never
changed.**

## §4 — ⚠ The leak found before the first census row was written

**75 of the 82 cohort accessions also appear in the census manifest; all 82 are in the roster.**
`coverage_payload` iterates the 82 and looks each accession up in a dict built from the database —
and **two of those dict-builders were not tranche-filtered.**

⚠ **The first census fold of `P04626` would have put a census `analysis_id` under HER2's accession**,
and the cohort's coverage row would then point at a fold measured under a **different span
definition**. ⚠ **No `ORDER BY`, so which row wins is whatever the database returns last —
nondeterministic, and silently so.** It would have **overwritten a reported result.**

⚠ **The guard's first version was over-broad**: it flagged `artifacts_present`, and **filtering that
would have made every census fold un-completable.** The exemption is now narrow and stated — a
surface must never mix populations; an operational lookup on one addressed row must work for every
row there is.

## §5 — ⚠ Ten jobs stranded on a key I left out

The first tranche-1 ingest omitted **`model_revision`**. `/claim` subscripts it, raised `KeyError`
**after** marking each job `claimed`, and ten jobs became **permanently stuck: `attempts=0`, no
error, nothing retryable, GPU idle.**

⚠⚠ **The dry run passed.** It validated slices, spans and DB invariants and **never called the
consumer it was writing for.** ⚠ **And my own pre-registration said *"model id/revision"* — the
document was right and the code implemented half of it.** At 1,307 rows this would have been
**1,307 silently stuck jobs**, and *a failure that leaves no trace in the row is worse than one that
fails loudly.*

**Fixed:** the ingest now builds a real `FoldSpec` from every payload **before any write**, and the
test **reads the required keys out of `app/artifacts.py`'s source** — ⚠ **not a hand-kept list,
because a hand-kept list is the thing that drifted.**
