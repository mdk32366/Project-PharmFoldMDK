# RESERVED — announced-but-unwritten entry numbers

> **What this file is for.** The citation invariant is: *every cited `D-NNN` / `F-NNN` / `S-NNN` /
> `DEP-NNN` in `docs/README.md` and `ARCHITECTURE.md` resolves to a real `### ` entry.* It was
> **RESTORED on 2026-08-03**, not inherited — D-062 had accumulated **thirteen** citations with no
> entry, and F-009 was cited by shipped UI and by `ARCHITECTURE.md` while existing only as a staged
> document. See `docs/README.md` method-note item 7.
>
> **The problem this file solves.** Some references point *forward*, at entries deliberately not
> written yet. A forward reference that announces its own absence is **not** the D-062 defect —
> D-062's harm was that citations treated a missing entry as **settled authority**, with nothing in
> the text suggesting it was missing. **But it is indistinguishable from the defect to a checker.**
>
> So the distinction cannot live as prose scattered through a method note: that works only while the
> set is small enough to remember. **This file is the whitelist. The checker whitelists this file
> and nothing else.**
>
> ## ⚠ THE RULE
>
> **An unresolved reference that is not listed below is a finding, immediately.** Not a cleanup item,
> not a note for later — the same class as D-062, found early.
>
> Reserving a number is **not** authorisation to do the work behind it. It reserves the integer and
> records what would unblock it. A reservation that is never written is retired here, in the open,
> with a reason.

## How to run the check

Named, not built — deliberately, per **D-074 decision 3** (*do not answer a finding with a framework
that becomes a second thing to drift*). It is one command, and it found two holes the first time it
was run:

```bash
python - <<'PY'
import re, pathlib

# D-156: the entries live in three files now, and `cited` reads the CODE.
ENTRY_DOCS = ['docs/decisions.md', 'docs/findings.md', 'docs/assumptions.md', 'docs/README.md']
CITE_DOCS  = ENTRY_DOCS + ['ARCHITECTURE.md', 'docs/SHIP-INDEX.md']
CITE_CODE  = ['core', 'app', 'scripts', 'tests', 'worker', 'db', 'ui/src']
NUM        = r'\b(?:D|F|S|DEP|A)-\d{3}\b'

def read(p):
    q = pathlib.Path(p)
    return q.read_text(encoding='utf-8') if q.is_file() else ''

# ⚠ D-156 defect 3: a heading may carry a SUFFIX (`### D-130-A`) or TWO ids
# (`### D-130-B / D-131`). The old regex captured the first only, which is the entire
# reason D-131 sat in this list for weeks. It was never a missing entry.
defined = set()
for d in ENTRY_DOCS:
    for line in read(d).splitlines():
        if line.startswith('### '):
            defined |= set(re.findall(NUM, line))

reserved = set(re.findall(r'^\| ~?~?\*\*([DFA]-\d+)\*\*', read('docs/RESERVED.md'), re.M))

# ⚠⚠ D-156 defect 2, and it is the one that failed SILENTLY for 38 days: `cited` read
# docs/README.md + ARCHITECTURE.md and nothing else, so 71 A- citations in shipped Python
# were outside the check's field of view. F-052's shape, turned on the invariant itself.
cited, where = set(), {}
for d in CITE_DOCS:
    for n in re.findall(NUM, read(d)):
        cited.add(n); where.setdefault(n, set()).add(d)
for root in CITE_CODE:
    for f in pathlib.Path(root).rglob('*'):
        if f.suffix in {'.py', '.ts', '.tsx', '.js', '.jsx', '.sql'} and '__pycache__' not in f.parts:
            for n in re.findall(NUM, f.read_text(encoding='utf-8', errors='ignore')):
                cited.add(n); where.setdefault(n, set()).add(str(f))

# ⚠ EVERY COUNT STATES ITS KEY. `cited` is a SET of distinct numbers, so re-citing an
# existing number cannot move it. On 2026-08-19 it was predicted to rise by someone who had
# run this the same morning; the prediction was arithmetic about the wrong object.
print(f'defined  {len(defined):4d}  | key: ids on `### ` headers across {len(ENTRY_DOCS)} entry docs'
      f' - HEADERS, not entries, and a compound header defines BOTH ids')
print(f'reserved {len(reserved):4d}  | key: `| **X-NNN**` rows in docs/RESERVED.md')
print(f'cited    {len(cited):4d}  | key: DISTINCT numbers in {len(CITE_DOCS)} docs AND in'
      f' {len(CITE_CODE)} code trees. A SET, not a total.')

missing = sorted(cited - defined - reserved)
print('UNRESOLVED AND UNRESERVED:', missing or 'none - invariant holds')
for n in missing:
    print(f'   {n} cited by: ' + ', '.join(sorted(where[n])[:4]))

# D-156: the next-free pointer, CHECKED rather than trusted. It drifted by 36 integers once
# because nothing in the gate asserted it.
print()
for ns in ('D', 'F', 'A'):
    live = sorted(int(x.split('-')[1]) for x in (defined | reserved) if x.startswith(ns + '-'))
    m = re.search(r'Next free `' + ns + r'-` integer: \*?\*?`' + ns + r'-(\d+)`',
                  read('docs/RESERVED.md'))
    if not m:
        print(f'{ns}- pointer: **MISSING** - no next-free sentence for this namespace')
        continue
    ptr = int(m.group(1))
    # The two failures this file has actually recorded, checked separately:
    #  (1) the pointer named a SPENT integer  - it drifted by 36 once, and would have
    #      handed a written number to the next writer.
    #  (2) the pointer named an integer with NO ROW - F-067, which is why it sat in the
    #      unresolved list. A placeholder row is REQUIRED, and is not itself an error.
    spent = f'{ns}-{ptr:03d}' in defined
    rowed = f'{ns}-{ptr:03d}' in reserved
    state = ('**SPENT - the pointer names a written entry**' if spent else
             '**NO ROW - pointer names an integer the table does not list**' if not rowed else
             'OK - unspent, and its placeholder row exists')
    print(f'{ns}- pointer: {ns}-{ptr:03d} | highest allocated {ns}-{max(live):03d} | ' + state)
PY
```

**Read the output, not the exit code.** An empty list is the only passing result.

### ⚠ Hash discipline: compare on normalised line endings

`git`'s `LF→CRLF` conversion on checkout means a document's committed bytes differ from its delivered
bytes — observed 2026-08-05 on `RULING-2026-08-05-A017-and-task-C-protocol.md`: **0 CRLFs delivered,
106 committed**, content byte-identical after normalising.

**Ruled:** hash comparison for text documents is performed **on `LF`-normalised bytes**. A raw-byte
mismatch that resolves under normalisation is **recorded, not escalated**; one that survives
normalisation is **stop-and-report, unchanged.**

⚠ **The reason is not convenience.** *"Hash before use, a mismatch is stop-and-report"* is
load-bearing on a channel that failed **three times** on 2026-08-05 — one document never arriving
across two reports, and another arriving twice. **A rule that raises a false alarm on every text
document trains its readers to ignore it, and that is how a real mismatch gets waved through.**
