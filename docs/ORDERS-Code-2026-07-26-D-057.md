## 0. The entry

### D-057 — A curation script that gathers evidence and refuses to draw the conclusion

- **Date:** 2026-07-26
- **Status:** Proposed → Accepted on merge.
- **Relates:** D-040 (Group B's definition, and the reservation of the judgement to the owner),
  D-016 (a claim names how it is known), D-024/D-027 (null with a reason), D-053 (curated file in
  `data/`, no live retrieval in the product).
- **Blocks nothing. Unblocks:** the labelling pass that D-041's fit waits on.

**Context.** Group B needs 82 rows and a first pass produced 16, with 66 unassessed. The bottleneck
is search recall across 82 targets under many aliases — mechanical work, done badly by hand and
well by a query. The judgement that follows is not mechanical and is not automated here.

**Decision 1 — the script gathers evidence; it never labels.** `is_group_b` is emitted **blank on
every row.** There is no code path that writes a label, and a test asserts no input produces one.
D-040 decision 1 reserved the classification to the owner because the calls turn on reading a
description and deciding what kind of molecule it is.

**Decision 2 — a registry miss is `needs_literature_check`, never `false`.** ClinicalTrials.gov
holds no preclinical work. **PODXL is a Group B positive on the strength of a preclinical ADC that
appears in no registry.** If silence became `false`, the script would manufacture confident wrong
labels — worse than blanks, because a blank announces its own ignorance and a `false` does not.

**Decision 3 — exclusion markers take precedence over ADC phrasing, and this was found by a test,
not by design.** `radioimmunoconjugate` contains the substring `immunoconjugate`. On first run the
IGF2R case — a radiolabelled antibody, explicitly excluded by D-040 — routed as a **probable
positive**. The calibration test caught it before the script ever reached a network. Recorded
because it is the D-040 error class reproduced by a heuristic, and because the fix is a precedence
rule that will look arbitrary to a future reader without this note.

**Decision 4 — offline tooling, not a runtime dependency.** The product retrieves nothing live
(D-053, and the 07-25 ruling on associations). The script runs once, emits a review sheet, and the
artefact of record stays a committed, cited file. A demo does not break because someone else's API
had a bad afternoon.

- **Deep-learning justification:** none, stated plainly. This is label-acquisition tooling for a
  model that is pre-registered and unfit. Its value is that it does **not** contaminate the labels —
  the last free parameter in D-041's experiment — with an automated judgement.
- **Consequences:** `scripts/curate_group_b.py`, `tests/test_curate_group_b.py`, and a dated review
  sheet under `data/derived/`. No dependency reaches the serving image.

## 1. ⚠ Fix this first — a defect in the handed-over script

**`requests` is in no requirements file in this repo** (verified: absent from `requirements*.txt`
and `worker/requirements.txt`). The script imports it at module scope, so **pytest collection would
fail and redden the gate.**

**Fix: defer the import into the functions that make network calls.** `classify_evidence` and
`parse_uniprot_aliases` — the only things the tests touch — must import with zero third-party
dependencies. Something equivalent to:

```python
def _http():
    import requests          # deferred: keeps the pure functions dependency-free in CI
    return requests
```

**Do not solve this by adding `requests` to the serving requirements.** `test_image_contents.py`
guards that boundary and this script has no business inside the image. If a dev/test requirement
file is the cleaner home, propose it — but the deferred import alone should be sufficient and is the
smaller change.

## 3. ⚠ Five things that will bite

**(a) If `probe` fails, STOP and report.** It exists because the API calls were written against a
retrieved spec, and retrieved specs go stale. It runs a **known-positive control** — searching
`enfortumab vedotin`, a marketed ADC — and fails if that returns nothing or fails to trip the ADC
flag. **Do not "fix" a failing probe by loosening the control.** A control that passes because it
stopped checking is the same failure mode as a contract test that stopped checking, and this is the
third time that trap has appeared today.

**(b) Never let the script emit `false`.** There is a parametrized test asserting no input produces
a determination. If a change makes it fail, the change is wrong.

**(c) The calibration tests are load-bearing.** NOTCH2, CSF1R, OSMR, IGF2R and SORT1 each assert
they are **not** routed as probable positives. If widening the payload-stem list makes one of them
red, that is the suite doing its job — narrow the change, do not relax the assertion.

**(d) Respect the rate limit.** ~50 requests/minute per IP is documented; the script sleeps 1.5 s
between calls, so a full pass is roughly 250 requests over 8–10 minutes. **Do not parallelise it.**
Getting the IP throttled mid-run costs more than the wait.

**(e) The review sheet is evidence, not a roster.** It must **not** be written to
`data/adc_reference_mapping.csv`. That path is the labelled artefact of record and only the owner
fills it.

## 6. If something here is wrong, say so

1. **The CTG query syntax may be wrong.** The script wraps terms as
   `TERM AND ("conjugate" OR "ADC")` against `query.term`. If the probe passes but real searches
   return nothing for known targets, the boolean syntax is the first suspect — report before
   rewriting.
2. **The alias strategy may over- or under-fetch.** It queries the symbol plus the two most specific
   UniProt aliases. Too few hits → propose more; too much noise → propose fewer. Do not silently
   change the count.
3. **This whole PR is optional tonight.** If D-055 and D-056 took the evening, say so and stop. It
   costs nothing to defer and it risks nothing that ships tomorrow.
