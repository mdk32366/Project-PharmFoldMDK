## §2 — The rulings that are actually blocking

These are the owner's, and nothing downstream moves without them.

**1. `P55073` — the selenocysteine row.** ⚠ Foldable **only by folding a different sequence**.
`U`→`C` (Se analogue of cysteine, backbone close) ⚠ **but the artifact would then describe a
sequence that is not the sequence of record — the F-025/MSLN defect**. `U`→`X` masks rather than
asserts. **Either way the substitution must be recorded IN the artifact.** Or leave it failed.

**2. Tranche 5 scope.** Three groups, and treating them as one unit is the mistake:
- **566 rows, 441–850 aa** — single-pass, in-context, **~$12–20 of A6000 time**. Routine.
- **69 rows, 851–1,026 aa** — 80 GB class, still in-context.
- ⚠⚠ **141 rows past 1,026 aa** — **outside the model's trained context.** A bigger card buys a
  structure, not an answer. **These do not belong in any single-pass tranche at any budget.**

**3. Tranche 6 — domain assembly**, for the ~10 modular repeat proteins (FAT1–4, LRP1/1B/2, USH2A,
ADGRV1, PKHD1L1). ⚠ **A different KIND of work**: needs a domain-boundary source, per-domain spans,
an assembly step and a `boundary_method` that says so. **Its artifacts do not belong in the same
population as single-pass folds.** A modelling design task, not a purchase.

## §3 — Work that is ready to start

**A. The length guard (F-035 remedy item 3).** `vram_guard.preflight()` exists and is **not wired
into the fold path**. ⚠ **It cannot simply be switched on** — it returns `REFUSED_NO_MEASUREMENT`
for unmeasured lengths, and **no ceiling has been measured for rental hardware**, so wiring it today
would refuse every legitimate rental fold. **Needs a `ceiling_climb` on the rented card first.**

**B. `reap_stale` is never called.** ⚠ Defined in `core/queue.py`, invoked by **no running
component** — no scheduler, no route. A `claimed` job whose worker dies has **no automatic recovery
path**. Currently harmless (nothing pending), and it applies to any interruption including a power
cut. **Unwritten; deserves a finding.**

**C. A category for unusable-confidence folds.** 11 tranche-4 rows are below pLDDT 50 — ⚠ **often
intrinsic disorder, which is a RESULT, not a failure.** Nothing distinguishes *low-confidence* from
*unusable for geometry*; they are just rows with a low number, which is the pattern this project
keeps fixing.

**D. Layer 3's catch path has no production evidence.** 332 clean folds prove it produces correct
artifacts, **not that it rescues anything** — no child has died. Tranche 5's long rows are where it
would matter.

## §4 — The habits that earned their keep, and the ones that failed

**Kept:**
- ⚠ **Capture `$?` on the line immediately after the command.** An assignment in between captures
  `tail`'s exit code.
- ⚠ **Assert that a string replacement applied.** An unasserted `.replace()` is a change that may
  not have happened — it silently shipped a row cap with no notice.
- ⚠ **Verify a deploy keyed on the commit SHA.** `gh run list --limit 1` right after a merge returns
  the **previous** run, and reports success for the wrong thing.
- ⚠ **Run the gate in a fresh `git worktree`** before claiming green on anything touching data
  files. A test that reads a gitignored artifact passes only on its author's machine.
- ⚠ **Every absence is a category with a cause.** It found F-036 and F-038.

**Failed:**
- ⚠⚠ **A rule applied to one shape and not another.** *"No hand-written SQL against production"* was
  honoured for `SELECT`s while a test suite — which does far worse — was treated as safe.
- ⚠ **A test can pin a defect as firmly as a behaviour.** Two this session did.
- ⚠ **A green local gate is not a gate** if CI cannot reproduce it.
