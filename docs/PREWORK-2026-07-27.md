## §3 — The scorer, once the labels exist (D-041 → code, no new decisions)

Everything below is spec'd. Order, with the traps that already bit once:

1. **`core/features.py` — the six D-027 features. Does not exist yet.**
   - Rg and SASA need CA coordinates from the stored structures; features 3–4 need per-residue
     pLDDT. Both are already in the fold artefacts.
   - **SASA needs a real algorithm** (Shrake–Rupley) — a dependency or ~40 lines by hand.
   - ⚠ **Compute features once and store them; never at request time.** A scientific-computing
     dependency in the serving path reddens `test_image_contents.py`. This is the D-047-class trap
     (resolve at the right time) in a new place.
2. **Record the labelled ∧ folded intersection before fitting**, and report it as a finding if it is
   materially under the expected count. At 79/82 folded, folding is no longer the binding
   constraint it was when D-041 was written — the labels are.
3. **`core/scorer.py` — fit + LOO percentiles.** Transcription of D-041, not design. λ by nested CV
   inside each fold; the held-out target never sees itself.
   - ⚠ **The label and the comparator must stay different quantities.** Label = Group B (ADC-antigen
     status). Comparator = the evidence score. If the evidence score is ever used as the label, the
     comparator predicts it by construction and D-041's negative-outcome test goes degenerate. This
     is the one that invalidates the result silently — hold it.
4. **The ranking table — UI Plan v2 §8.** The centrepiece, built last, on real scores. Same
   discipline as everything shipped today: derived, pinned, honest about its own confidence.

**Timing, honestly:** this is two-plus sessions after the labels are done, and the labels are a real
curation pass. It is a post-delivery arc, not a tomorrow one. That is the correct shape — it is
better delivered as a fitted model with pre-registered results than as a rushed one, and the log
already proves you chose the former under deadline pressure.
